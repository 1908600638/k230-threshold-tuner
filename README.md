# K230 脱机阈值调试器

在 K230 开发板上**离线**调节 LAB 颜色阈值的小工具：摄像头实时预览，直接在触摸屏上加减 L/A/B 六个参数，边调边看二值化效果，确认后把阈值存到 SD 卡。

全程在板子上跑，不需要连电脑，适合现场调颜色识别参数。

## 功能

- 摄像头实时预览 + FPS 显示
- 触摸屏调节 6 个阈值（L1、L2、A1、A2、B1、B2），每项支持 ±1 / ±10
- 二值化画面实时预览，调参效果立刻可见
- 一键「反转」：取当前阈值以外的区域
- 「确认」保存到 `/sdcard/threshold.dat`，下次开机自动读回
- 「返回」放弃本次修改并还原进界面前的参数
- 「复位」恢复到默认阈值
- 板载 KEY 按键控制 LED

## 实现原理

### 整体流程

```
上电
 │
 ▼
从 /sdcard/threshold.dat 读阈值 ── 文件不存在就用默认值
 │
 ▼
初始化摄像头（800×480 RGB565）→ 初始化 ST7701 屏幕 → 初始化触摸
 │
 ▼
主循环 while True
 ├── 拍一帧 sensor.snapshot()
 ├── 读触摸点 button_touch()：命中哪个按钮就改哪个参数
 ├── 处理 反转 / 复位 / 返回 / 确认 四个标志位
 ├── 按 lcd_flag 画界面 1 或界面 2 并推屏
 └── 扫描板载 KEY
```

### 两个界面

**界面 1（预览态）** — 原图 + 左上角 FPS 和当前阈值，右下角有一个「调试」按钮。

**界面 2（调节态）** — 二值化图 + 四角功能按钮 + 左侧 6 行参数调节区。

进入界面 2 时会把当前阈值存到 `prev_*` 变量里，「返回」时从这里还原。

### 触摸分区

触摸坐标是**按 800×480 写死**的，判定方式是判断触点落在哪个矩形区域里：

功能按钮：

| 按钮 | 触发区域 | 位置 |
|---|---|---|
| 调试（界面 1） | x ≥ 750，y ≥ 450 | 右下角 |
| 返回（界面 2） | x ≤ 55，y ≤ 40 | 左上角 |
| 反转（界面 2） | 370 ≤ x ≤ 430，y ≤ 40 | 顶部中间 |
| 确认（界面 2） | x ≥ 750，y ≤ 40 | 右上角 |
| 复位（界面 2） | 370 ≤ x ≤ 430，y ≥ 450 | 底部中间 |

参数调节区，6 行分别对应 L1、L2、A1、A2、B1、B2：

| 行 | y 范围 | 参数 |
|---|---|---|
| 1 | 80 ~ 120 | L1 |
| 2 | 150 ~ 190 | L2 |
| 3 | 220 ~ 260 | A1 |
| 4 | 290 ~ 330 | A2 |
| 5 | 360 ~ 400 | B1 |
| 6 | 430 ~ 470 | B2 |

每行横向四个档位：

| 位置 | x 范围 | 步进 |
|---|---|---|
| +1 | 0 ~ 30 | +1 |
| +10 | 90 ~ 140 | +10 |
| -10 | 670 ~ 720 | -10 |
| -1 | x ≥ 760 | -1 |

### 参数范围限制

LAB 各通道的合法范围不同，每次修改后都会夹紧：

| 通道 | 范围 |
|---|---|
| L | 0 ~ 100 |
| A | -128 ~ 127 |
| B | -128 ~ 127 |

### 「反转」的逻辑

反转不是简单取反，而是**在合法范围内取阈值之外的部分**，并且要保证 `下界 ≤ 上界`：

```python
L2 = orig_L1 - 1          # 原来下界减一变成新上界
if orig_L2 < 100:
    L1 = orig_L2 + 1      # 原来上界加一变成新下界
    L2 = 100
```

A、B 通道同理，只是范围换成 -128 ~ 127。如果算出来下界超过上界，就退回整段范围。

### 阈值怎么存

纯文本 CSV，一行六个整数，写在 `/sdcard/threshold.dat`：

```
0,100,-128,128,-128,128
```

开机时 `try` 读文件，读不到（首次运行）或格式不对就落到默认值。

## 代码结构

单文件，约 250 行，按功能分段：

| 位置 | 作用 |
|---|---|
| 第 1~7 行 | 导入 CanMV 的 machine / media 模块 |
| 第 9~24 行 | 全局标志位、默认阈值、`prev_*` 备份变量、存档路径 |
| 第 26~38 行 | 从 SD 卡读阈值，失败则用默认值 |
| 第 40~48 行 | 摄像头与屏幕初始化 |
| 第 50~60 行 | GPIO（LED 52 / KEY 21）、触摸、时钟 |
| `save_parameters()` | 把当前阈值写回 SD 卡 |
| `ui_1()` | 画界面 1（原图预览） |
| `ui_2()` | 画界面 2（二值化 + 按钮文字） |
| `invert_threshold()` | 反转阈值范围 |
| `update_threshold()` | 把参数夹到合法范围并同步到 `threshold` |
| `button_touch()` | 读触摸并按坐标分区改参数、置标志位 |
| 主循环 | 抓帧 → 处理标志位 → 画界面 → 扫按键 |

关键的三个函数：

- **`button_touch()`** — 全部交互逻辑，靠一串 `if/elif` 判断触点落在哪个格子
- **`invert_threshold()`** — 反转算法
- **`update_threshold()`** — 范围夹紧 + 同步到 OpenMV/CanMV 用的 `threshold` 列表

> `threshold` 必须是**列表里套元组**（`[(L1,L2,A1,A2,B1,B2)]`），这是 CanMV 的 `img.binary()` 要求的格式，所以每次改完参数都要同步更新 `threshold[0]`。

## 环境要求

| 项 | 要求 |
|---|---|
| 开发板 | K230（01Studio CanMV K230 等） |
| 固件 | CanMV / MicroPython（带 `machine`、`media` 模块） |
| 屏幕 | ST7701 3.5 寸 MIPI 屏，分辨率 800×480 |
| 存储 | SD 卡（阈值文件存在这里） |
| 摄像头 | 板载 GC2093 等，能跑 800×480 |
| 电脑 | 不需要（脱机运行），只在烧录脚本时需要 |

> 换别的屏幕要改 `Display.init()` 的型号和 `set_framesize()` 的尺寸，同时触摸坐标分区也得跟着改。

## 使用

1. 把 `.py` 文件拷到开发板（U 盘模式或 CanMV IDE 保存到板子）
2. 上电或按复位运行
3. 界面 1 看到实时画面和 FPS，点**右下角「调试」**进入调节界面
4. 在二值化画面上按左侧 6 行按钮调参数，右边是原图效果对照
5. 调到满意后点**右上角「确认」**，阈值写入 SD 卡
6. 点**「返回」**则放弃修改；点**「复位」**回到默认值，再点「确认」才会保存

调好的阈值可以直接抄出来用在你自己的 `find_blobs()` 里，或者运行后从 SD 卡读 `threshold.dat`。

| 依赖 | 用途 | 说明 |

## 说明

- 触摸坐标是**按 800×480 硬编码**的，改分辨率必须同步改 `button_touch()` 里的区间和 `ui_2()` 里的绘制位置
- 只针对 ST7701 3.5 寸 MIPI 屏验证，其它屏要改 `Display.init()` 的参数
- LED 用 GPIO52、KEY 用 GPIO21，不同板子的引脚可能不一样，要按原理图改
- 阈值格式是 LAB 的 `(L1,L2,A1,A2,B1,B2)`，和 OpenMV 的 `threshold` 一致
- 代码偏工具向，够用为主，没有做异常恢复和界面美化
